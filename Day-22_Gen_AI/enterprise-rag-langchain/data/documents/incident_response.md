# Incident Response Guide

## Incident Severity

Incidents should be assessed based on:

- User impact
- Business impact
- Scope
- Duration
- Availability of workarounds

## Initial Response

When an incident is detected:

1. Confirm that the issue is reproducible.
2. Determine the affected service.
3. Determine the affected users or workflows.
4. Establish the incident timeline.
5. Review recent deployments and configuration changes.
6. Begin collecting relevant logs and metrics.

## Investigation

Investigators should distinguish between:

- Symptoms
- Immediate technical errors
- Contributing factors
- Root cause

An observed error should not automatically be treated as the root cause.

## Communication

Incident updates should include:

- Current impact
- Known facts
- Investigation status
- Mitigation actions
- Next update time

## Resolution

After mitigation:

1. Confirm service recovery.
2. Validate critical workflows.
3. Continue monitoring.
4. Document the root cause.
5. Identify preventive actions.
